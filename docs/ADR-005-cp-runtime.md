# ADR-005. Доступность Control Plane статического кластера

Статус — предложено. Основа — ADR-003 и #96. Схема регионального доступа относится к #46.

CP API работают active-active поверх линейризуемого StateStore. Региональные API используют общий etcd namespace. Gateway и CP Agent получают список API в порядке предпочтения и переключаются при транспортной недоступности. Два API в одном регионе и два API в разных регионах имеют одинаковые требования к доступности кворума etcd. Пропажа удалённого API или WAN может остановить управление без остановки уже работающего Raft.

CP и etcd имеют отдельные доверенные CA. В профиле mTLS CP удостоверяет клиентские роли по URI SAN. Агент может обновлять heartbeat только для своей пары node–region. CP проверяет cluster ID на каждом RPC. Серверные сертификаты проверяются по имени или IP endpoint. В профиле без сертификатов сохраняется локальный режим PoC.

Gateway и агент сохраняют принятый снимок в отдельном файле каждого процесса. Формат содержит version, cluster ID, region, client ID, время принятия и контрольную сумму. Gateway дополнительно сохраняет максимальный наблюдавшийся Raft term и конфликт лидеров для маршрутизируемых групп. Замена файла атомарна. Опрос и файловые операции выполняются вне клиентских RPC.

При холодном старте снимок Gateway допускает строгие чтения через прежние маршруты, пока Raft подтверждает запрос. Запись разрешается после получения полного конфига от CP. Агент применяет такое же правило при проверке полномочий на запись. Для уже подтверждённой карты отказ CP сохраняет штатный режим деградации. Доверенная граница дискового снимка — локальный каталог процесса и его права доступа.

Etcd MVCC revision нужна для транзакций и наблюдателей. `config_revision` — монотонная ревизия опубликованной топологии. Восстановление backup с bump etcd revision требует отдельной публикации `config_revision` выше значения, наблюдавшегося до отказа. Перед восстановлением останавливают издателей, после него устанавливают нижнюю границу ревизии в CP API. При замене инкарнации Raft-группы требуются отдельный идентификатор группы в контракте и порядок миграции.
