# ADR-003. StateStore Control Plane в etcd

Статус — принято для первого среза #45.

## Решение

CP API использует существующий интерфейс `statestore.Store`. При запуске
`-store etcd` состояние хранится под общим для кластера префиксом.
`-store memory` остаётся backend по умолчанию для локального PoC.

| Ключ под префиксом | Содержимое | Срок хранения |
| --- | --- | --- |
| `/config/snapshot` | Полный JSON `cpconfig.Config` с `revision` | До следующей публикации |
| `/heartbeats/<base64url(node_id)>` | Последний полный статус ноды | Lease |
| `/heartbeat-receipts` | Время получения последнего heartbeat по настроенным парам нода–регион | Пока пара непрерывно присутствует в топологии |

Снимок содержит ревизию в том же значении. `ApplyConfig` валидирует новый
снимок и сравнивает его ревизию и число партиций с опубликованными. Транзакция
проверяет `ModRevision` ключа снимка. Если другой издатель успел записать
раньше, проверка повторяется с новым снимком. Bootstrap использует create-only
транзакцию. [Транзакции etcd](https://etcd.io/docs/v3.6/learning/api/#transaction).

CP API подтверждает валидный heartbeat и сохраняет его статус только для
настроенной пары нода–регион. Запись сверяет `ModRevision` снимка и обновляет
статус и время получения одним commit. При удалении пары публикация сверяет
`ModRevision` документа с временами получения и удаляет её запись той же
транзакцией, что публикует новую топологию. Один документ позволяет удалить
произвольное число пар в пределах лимита размера запроса etcd и приводит к
конкуренции heartbeat за этот ключ.

Отдельный lease на heartbeat позволяет обновлять статус без привязки к
сессии CP API. Истечение lease удаляет статус, а время получения остаётся
доступным для метрики. Для маршрутизации действующий lease учитывается после
первого heartbeat за текущий период присутствия пары в топологии. После её
удаления и быстрого повторного добавления Gateway ждёт свежего heartbeat.
Топология, статусы и времена получения читаются для
Gateway в одной транзакции. Оба backend используют проекцию #67. Она
учитывает готовность назначенных реплик в максимальном наблюдаемом Raft term
и снимает готовность при конфликте лидерства в этом term. Ошибка чтения приводит к `Unavailable`, при
этом Gateway продолжает использовать принятую карту. Счётчики ошибок CP
остаются доступны в `/metrics`. [Leases etcd](https://etcd.io/docs/v3.6/learning/api/#lease-api).

## Границы

Первый срез использует линейризуемые чтения по запросу. Публикация после
bootstrap доступна через `Store.ApplyConfig`. Controller, региональный CP
и сохранение last-known-good на диске клиентов относятся к отдельным задачам.
