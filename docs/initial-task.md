# Геораспределённый кеш профилей/соцграфа

## Срок готовности проекта
22.01.2027

## Основные требования

### Цель проекта
Распределенный кеш горячих сущностей с событийными инвалидациями, версионированием и межрегиональной репликацией.

### Описание проекта (проектная задача)
Снизить нагрузку на первичное хранилище и задержку чтения, сохраняя определенные гарантии свежести при гонках и multi-DC работе.

### Обязательная часть: базовый состав проекта и MVP
- cache-aside
- событийная инвалидация
- версионирование записей
- репликация между двумя логическими регионами
- метрики hit rate и latency

### Функциональные требования
- чтение и прогрев кеша
- изменение источника и доставка инвалидации
- защита от отката старой версии
- настраиваемый TTL

### Технические требования и ограничения
- явная модель bounded staleness или eventual consistency
- pub/sub для инвалидаций
- p95/p99 latency, hit rate и доля устаревших ответов
- chaos-тесты регионов

### Опциональные требования и усложнения
- stale-while-revalidate
- защита от cache stampede
- репликация только hot keys
- адаптивный TTL
- TinyLFU/ARC в упрощённом виде

## Требования заказчика

### Cache-aside
Приложение запрашивает данные из кэша, а при их отсутствии, получает их из БД и самостоятельно загружает в кэш. Кэш не запрашивает информацию из БД самостоятельно

### Топология
Произвольное количество регионов, в каждом регионе несколько инстансов для обеспечения надежности

### Балансировка
Входит в состав реализованного проекта, без необходимости настраивать ее вручную

### Прогрев кэша
Реализуется в составе решения. Главное, чтобы в момент включения в балансировку, инстанс уже имел необходимые данные. Данные могут иметь разную степень "полезности"

### Персистентность
Достаточная для восстановления после падения

### Инвалидация
Происходит по событиям об изменении данных, источник событий должно быть возможно заменить. Под pub/sub имеется ввиду именно эта подписка на изменение данных

### Переиспользование технологий
Допустимо, при наличии достаточного количества самостоятельной разработки на команду из 6 человек

### Профиль нагрузки
- `10000 RPS` на чтение
- `500 RPS` на запись
- размер записи `10кб`
