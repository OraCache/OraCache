# ADR-002: единый регион записи

Статус: single write-region предметно принят 02.11.2026. Область: target. Основание E-002; текущее подтверждение async outbox — E-017.

## Контекст

Копии кэша должны существовать в нескольких регионах. Если каждый регион независимо принимает исходные изменения одного ключа, системе нужен способ разрешать конкурирующие записи. В обсуждении уточнена более узкая модель: исходные записи принимает один уполномоченный регион.

Регион записи отличается от Raft-лидера. Лидер упорядочивает команды своей группы; в регионе-копии тоже может быть локальный лидер, принимающий импорт изменений. Его избрание не даёт региону права принимать исходные записи приложения.

## Решение

[Использовать единый регион записи](../REQUIREMENTS.md#r-002). Запрос на запись, пришедший через другой регион, направляется к уполномоченному writer-региону. Межрегиональная репликация остаётся частью конечного решения. [Асинхронная доставка через outbox](../REQUIREMENTS.md#r-015) подтверждена владельцем как выбранный механизм; детали доставки и подтверждения клиенту остаются в RFC-003.

## Основания и последствия

Принятое ограничение сужает место упорядочивания исходных команд кэша. Несколько независимых writer-регионов потребовали бы отдельного разрешения конфликтов. Обсуждалась и общая Raft-группа через WAN, но оснований объявлять её принятым решением нет. Полный сравнительный выбор протокола этим ADR не реконструируется.

Запись из удалённого региона зависит от связи с writer-регионом. Асинхронная копия может отставать. Единый writer кэша также не определяет порядок транзакций основной БД и сам по себе не решает гонку задержанного заполнения.

## Незакрытые детали и подтверждение

Нужно определить момент успешного ответа, чтение собственных записей в другом регионе и [передачу полномочий после отказа](../REQUIREMENTS.md#r-016). Fencing означает механизм, запрещающий старому writer продолжать записи после передачи полномочий; конкретный механизм не выбран.

Глобальная линейризуемость, отсутствие потерь при уничтожении региона, автоматическое переключение и численные RPO/RTO не приняты этим решением. В [RFC-003](../rfc/RFC-003-recovery.md) перечислены варианты и отказные проверки. Однорегиональный PoC не проверяет маршрутизацию записей между регионами.
