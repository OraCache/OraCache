# ADR-003: три реплики данных

Статус: RF3 предметно принят заказчиком 02.11.2026. Область: target; в PoC — три storage-процесса одного шарда. Основания E-003, E-010, E-017.

## Контекст

Шардирование делит пространство ключей между группами, а репликация создаёт несколько копий данных каждой группы. Для оценки ресурсов необходимо различать число шардов и число их реплик. Предварительный расчёт с двумя копиями не был итоговым выбором: в предметном обсуждении принят replication factor 3, сокращённо RF3.

## Решение

[Использовать три реплики данных](../REQUIREMENTS.md#r-003).

Применение Raft и наличие шардов отдельно подтверждены владельцем. Этот ADR не задаёт число шардов и не утверждает конкретную схему регионального размещения целиком.

## Основания и последствия

Прямое предметное согласие на RF3 сильнее предварительного sizing с RF2. Для Raft большинство группы из трёх составляет две реплики; при потере одной группа может продолжить работу, если остальные связаны и имеют необходимое состояние. Это условная способность протокола, не гарантия доступности при любом отказе.

Заказчик потребовал [одинаковые конфигурации storage-pod](../REQUIREMENTS.md#r-003), но не ограничил проект единственной схемой размещения. Команда выбрала один pod на экземпляр шарда как простой вариант. Ни RF3, ни требование одинаковых конфигураций сами по себе не запрещают размещать в одном процессе участников разных групп.

Три копии требуют учитывать память, сеть и восстановление каждой реплики. Размещение нескольких peers в процессе может уменьшить число процессов, но связывает их отказы и требует отдельного обоснования распределения нагрузки. Это анализ компромисса, не свидетельство рассмотренного и отвергнутого командой дизайна.

## Незакрытые детали и подтверждение

PoC показал смену лидера после остановки одного процесса. Он не доказывает независимость физических доменов отказа. Для target нужно проверить размещение реплик, [нагрузку и запас на восстановление](../REQUIREMENTS.md#r-022). [Число шардов, отображение ключей и операции переноса](../REQUIREMENTS.md#r-021) рассматривает [RFC-004](../rfc/RFC-004-topology.md). Ресурсные бюджеты остаются незаданными.
